# 安卓课程表应用设计规格

## 1. 目标

构建一款名为“我的课表”的原生安卓应用，首次安装即包含宋柯元 2026–2027 学年第一学期课表。应用支持按教学周和星期查看课程，以及在手机本地新增、修改、删除和恢复课程。最终交付可直接安装的 Debug APK 与完整 Android Studio 源码。

## 2. 范围

### 包含

- 以 2026-08-31 为第 1 周周一，总周数默认为 16 周。
- 每日时间轴首页，可切换周次和星期。
- 课程详情，以及课程、教师、地点、星期、节次、周次的增删改。
- 未提供上课时间的课程进入“待安排”列表。
- 本地持久化、时间冲突检查、恢复原始课表。
- Android 8.0（API 26）及以上系统。
- 中文界面、浅色和深色系统主题、基础无障碍标签。

### 不包含

- 账号、云同步、联网接口、通知提醒、桌面小组件。
- Excel 文件的运行时导入或导出。
- iOS、网页或小程序版本。
- 教务系统登录或自动同步。

## 3. 用户体验

### 3.1 课程表首页

首页采用已确认的“每日时间轴”布局：

- 顶部显示“第 N 周”和该周日期范围，并提供上一周、下一周按钮。
- 下方显示周一至周日七个日期按钮；默认选择当天。
- 当天课程按开始节次排序。课程卡显示开始和结束时间、课程名称、节次、地点、教师。
- 点击课程卡进入编辑页；右下角“新建课程”进入空白编辑页。
- 底部导航包含“课程表”“待安排”“设置”。
- 启动时根据本地日期计算教学周。日期早于第 1 周时显示第 1 周，晚于最后一周时显示第 16 周；用户始终可以手动切换。

### 3.2 课程编辑

编辑页包含：

- 课程名称，必填。
- 课程代码，可选。
- 教师，可选。
- 教室，可选。
- 备注，可选。
- 一个或多个上课安排。每个安排包含星期、开始节次、结束节次和上课周次。

用户可以为同一课程增加多个安排，以表达一周多次上课或不同周次使用不同教室。保存前执行字段和冲突校验。编辑既有课程时提供“删除课程”，删除前要求确认；删除课程会同时删除其所有上课安排。

### 3.3 待安排

没有任何上课安排的课程显示在“待安排”列表。点击后使用同一个课程编辑页；补齐至少一个有效安排并保存后，该课程从待安排列表移除并出现在课程表中。新建课程也允许暂不填写安排，保存后进入待安排列表。

### 3.4 设置

- 可修改第 1 周周一日期，默认 2026-08-31。
- 可修改总教学周数，允许 1–30 周，默认 16 周。
- “恢复原始课表”在二次确认后清除用户修改并重新写入本规格第 6 节的数据，同时恢复默认学期设置。

## 4. 技术架构

- Kotlin 原生 Android 单 Activity 应用。
- Jetpack Compose 与 Material 3 构建界面。
- UI 层使用 ViewModel 暴露不可变状态并处理用户操作。
- Repository 作为 UI 与数据源之间的唯一接口。
- Room 保存课程、上课安排和学期设置；应用不申请联网权限。
- 小型应用不引入独立 domain 模块或依赖注入框架。依赖由应用级容器显式创建。
- 日期计算使用 `java.time.LocalDate`。

### 4.1 数据模型

`CourseEntity`

- `id: Long`
- `name: String`
- `code: String?`
- `teachers: String?`
- `note: String?`

`MeetingEntity`

- `id: Long`
- `courseId: Long`
- `weekday: Int`，1 表示周一，7 表示周日。
- `startPeriod: Int`，1–12。
- `endPeriod: Int`，不得小于开始节次。
- `weekMask: Long`，第 1–30 位表示对应教学周是否上课。
- `location: String?`

`SemesterSettingsEntity`

- 单例主键。
- `firstWeekMonday: LocalDate`
- `totalWeeks: Int`

课程与上课安排是一对多关系。Room 外键负责级联删除。数据库仅在首次创建时写入原始数据；即使用户删除全部课程，重启也不会自动重建。只有设置页的显式恢复操作可以重新写入原始数据。

## 7. 校验与错误处理

- 课程名称去除首尾空白后不得为空。
- 星期必须为 1–7，节次必须为 1–12，结束节次不得早于开始节次。
- 上课周次必须至少包含一周，且不得超过当前总教学周数。
- 两个不同安排在星期相同、节次区间重叠且周次集合有交集时视为冲突。保存被阻止，并显示冲突课程、星期、节次和重叠周次。
- 编辑现有安排时，冲突检测排除该安排自身。
- 数据库操作失败时保留用户编辑内容并显示可重试的中文错误，不让界面显示未保存的数据为已保存状态。
- 恢复课表和删除课程都需要确认，取消后不得修改数据库。

## 8. 状态与数据流

1. Room DAO 通过 Flow 发布课程、安排和设置。
2. Repository 组合所选周次与星期对应的课程，并按开始节次排序。
3. ViewModel 将加载中、内容、空状态和错误转换为单一界面状态。
4. Compose 界面只渲染状态并发送用户操作。
5. 保存成功后 Room 的 Flow 自动刷新课程表和待安排列表。

## 9. 测试与验收

### 自动测试

- 周次计算：2026-08-31 为第 1 周，2026-09-07 为第 2 周，学期前后正确限制到首尾周。
- 周次集合：连续周、离散周和组合周正确转换为 `weekMask`。
- 冲突检测：相同和不同星期、相邻和重叠节次、相交和不相交周次、编辑自身排除。
- 初始数据：12 门已安排课程、3 门待安排课程及全部地点、教师、周次、节次正确。
- Repository：新增、修改、删除课程后结果与待安排状态正确。
- Compose 界面：切换周次和星期、打开编辑页、校验提示、保存和删除确认。

### APK 验收

- 完整单元测试通过。
- Debug APK 构建命令成功退出，APK 位于标准 Gradle 输出目录。
- 使用 Android 工具验证 APK 包名、最低系统版本和签名。
- 若本机具备可用模拟器或安卓设备，额外安装并执行一次启动与核心编辑流程；若环境没有设备，明确报告未执行设备级验证。
- APK 不声明互联网权限，在 Android 8.0 及以上系统可安装。
